
# Prismotive — Architecture Overview

**Status:** Approved design; implementation pending

## Architecture Style

Prismotive uses a modular, framework-independent architecture.

Three animation engines share common infrastructure without
depending on one another.

## High-Level Modules

### Public API

The public API will expose:

- `animatedBorder()`
- `animatedWave()`
- `cursorTrail()`
- `createTheme()`

The API will be exported through `src/index.ts`.

### Shared Core

The shared core will manage:

- Target resolution
- Configuration validation
- Animation lifecycle
- Instance ownership
- Resource cleanup
- Visibility management
- Error handling
- Animation scheduling

### Animation Target Resolution

The internal `resolveTarget()` utility converts a CSS selector
or existing HTMLElement into a validated target element.

Supported behaviour:

- CSS ID, class and other valid selectors
- First matching HTML element
- Existing HTML element references
- Current-document targets

Invalid selectors, missing elements, unsupported element types
and detached targets are rejected.

The resolver does not modify the DOM.

Module imports are safe in Node.js environments. Resolving a
target requires a browser environment.

Structured error integration is planned for Step 5.4.

### Theme Engine

The theme engine will provide:

- Five predefined palettes
- Custom palette validation
- Theme resolution
- Immutable theme objects

### Theme Resolution

The internal theme resolver accepts built-in preset names and custom theme objects.

Preset names resolve to shared immutable palette objects.

Custom themes are validated and normalised using createTheme().

The resolver preserves valid immutable references where safe and creates immutable copies of mutable inputs.

Invalid themes are rejected rather than silently replaced with a default palette.

### Animation Engines

**Border engine

Uses CSS-based gradient animation.

**Wave engine

Uses Canvas 2D and mathematical wave calculations.

**Cursor trail engine

Uses Canvas 2D, pointer events, and bounded particles.

## Module Dependency Rules

- Public API modules may depend on effect and theme modules.
- Effect engines may depend on shared core utilities.
- Effect engines must not depend on other effect engines.
- The theme engine must remain independent of effect engines.
- Browser-specific APIs must not execute during module import.
- Internal modules must not be exposed unintentionally.

## Rendering Architecture

CSS is selected for animated borders.

Canvas 2D is selected for waves and cursor trails.

Canvas effects will share a scheduler based on
`requestAnimationFrame()`.

The scheduler must stop requesting frames when no rendering
work remains.

## Lifecycle Contract

Every animation instance will expose:

- `pause()`
- `resume()`
- `update(options)`
- `destroy()`
- `state`

Public states:

- running
- paused
- destroyed

Automatic suspension must not override manual pausing.

## Error Handling

Prismotive will use structured errors with stable codes.

Invalid initialisation and configuration operations will
produce synchronous errors.

Unexpected asynchronous rendering failures will be reported
through a documented error callback.

## Resource Management

Every acquired resource must have a cleanup path.

This includes:

- Event listeners
- Observers
- Animation frame subscriptions
- Decorative DOM elements
- Canvas resources
- Instance registrations

Successful destruction must be idempotent.

## Browser and Framework Compatibility

Prismotive targets modern browsers and framework-independent
integration.

Module imports must be safe in server environments.

Animation initialisation requires a supported browser environment.

Browser compatibility will be verified through automated tests.

## Known Architectural Risks

- CSS border isolation
- Content Security Policy compatibility
- Canvas memory consumption
- Animation frame performance
- Detached DOM resource retention
- Tree-shaking effectiveness

These risks require implementation and verification.

## Distribution

- ECMAScript modules
- JavaScript generated by Vite
- TypeScript declarations generated by TypeScript
- Published through npm after release verification

CommonJS distribution is not currently planned.
